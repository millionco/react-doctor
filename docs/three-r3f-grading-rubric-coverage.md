# Three.js and React Three Fiber grading-rubric coverage

React Doctor statically diagnoses code defects. It does not claim that source inspection can
replace the rubric's Playwright probes, temporal evidence, prompt profile, or craft review.
This map keeps that boundary explicit so adding rubric coverage does not turn intentional fixed
cameras, flat styles, static scenes, or repeated formations into false positives.

The rule pairs below use Three.js import provenance and closed, locally provable object graphs.
They abstain when spreads, callbacks, custom components, imported scene members, shader materials,
or helper mutations can change the result.

## Source-request coverage

The original request included a core Three.js/R3F implementation checklist and four explicit GPU
performance directives before the grading rubric. Those requirements are part of this coverage
contract rather than implicit background.

### Explicit GPU and instancing directives

| Directive                                                                                         | Three.js rule                                                                    | React Three Fiber rule                                                       | Reporting boundary                                                                                                                                               |
| ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use `InstancedMesh` for many copies of shared geometry and material                               | `three-prefer-instanced-mesh`                                                    | `r3f-prefer-instanced-mesh`                                                  | Reports only provably repeated rendered meshes with stable shared resources and no incompatible per-object semantics.                                            |
| Favor GPU animation for repeated instance transforms                                              | `three-prefer-gpu-instanced-animation`                                           | `r3f-prefer-gpu-instanced-animation`                                         | Reports repeated per-instance matrix/color writes in a recognized frame loop; one-time setup and open helpers abstain.                                           |
| Animate repeated vertex positions in shaders or GPU state instead of rewriting buffers each frame | `three-prefer-gpu-position-animation`                                            | `r3f-prefer-gpu-position-animation`                                          | Reports repeated position-buffer entry mutations in a recognized animation loop or `useFrame`; bulk one-time initialization and unrelated attributes stay quiet. |
| Compute particle position and transform evolution on the GPU where possible                       | `three-prefer-gpu-position-animation` and `three-prefer-gpu-instanced-animation` | `r3f-prefer-gpu-position-animation` and `r3f-prefer-gpu-instanced-animation` | Particle vocabulary alone never reports. The detector requires the harmful CPU-per-frame mutation shape, so static or low-cardinality systems are not penalized. |

These boundaries follow the current Three.js guidance for [`WebGLRenderer.setAnimationLoop`](https://threejs.org/docs/pages/WebGLRenderer.html), [`InstancedMesh`](https://threejs.org/docs/pages/InstancedMesh.html), and [`BufferAttribute` updates](https://threejs.org/docs/pages/BufferAttribute.html), together with R3F's managed [`Canvas`](https://r3f.docs.pmnd.rs/api/canvas), [`useFrame` and `useLoader`](https://r3f.docs.pmnd.rs/api/hooks), [automatic disposal](https://r3f.docs.pmnd.rs/api/objects), and [instancing guidance](https://r3f.docs.pmnd.rs/advanced/scaling-performance).

## Added static contracts

| Contract                                       | Three.js                              | React Three Fiber                   | Static reporting boundary                                                                                                                                                                                                           |
| ---------------------------------------------- | ------------------------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Normal-mapped custom geometry requires normals | `three-require-lit-material-normals`  | `r3f-require-lit-material-normals`  | A closed `BufferGeometry` defines `position`, does not define or compute `normal`, and is paired with a built-in lit material that applies a non-null `normalMap`. Unlit, shader, unmapped, and open materials are excluded.        |
| Mapped custom geometry requires UVs            | `three-require-uv-for-texture-map`    | `r3f-require-uv-for-texture-map`    | A closed `BufferGeometry` defines `position`, has none of `uv`, `uv1`, `uv2`, or `uv3`, and is paired with a built-in material that has a non-null UV-sampled map.                                                                  |
| Strong metal requires an environment           | `three-require-environment-for-metal` | `r3f-require-environment-for-metal` | A closed rendered scene or inline `Canvas` contains a standard or physical material with statically known `metalness > 0.5`, no material environment map, and no scene environment. Direct lights do not satisfy metal reflections. |
| PBR requires a lighting source                 | `three-require-lighting-for-pbr`      | `r3f-require-lighting-for-pbr`      | A closed rendered scene or inline `Canvas` contains a standard or physical material and no direct light, scene environment, material environment map, light map, or intentional emissive source.                                    |

These contracts follow the Three.js definitions of [BufferGeometry attributes](https://threejs.org/docs/pages/BufferGeometry.html), [texture UV channels](https://threejs.org/docs/pages/Texture.html), and [environment lighting for `MeshStandardMaterial`](https://threejs.org/docs/pages/MeshStandardMaterial.html). Since Three.js r183, renderers [fall back to derivative-based flat shading](https://github.com/mrdoob/three.js/pull/32831) when ordinary lit geometry has no normal attribute, so the normals rules intentionally report only the normal-map case where that fallback does not apply.

## Grading-protocol boundary

The rubric also specifies how a grader combines evidence. Those instructions are not application
source patterns and therefore do not become lint diagnostics.

| Rubric protocol                                          | React Doctor responsibility                                                                                                                    | External grader responsibility                                                                                                                                                                  |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep the probe floor and craft review separate           | Report source diagnostics with their normal rule identity, category, severity, and confidence boundary                                         | Report Plane 1 and Plane 2 side by side and never convert diagnostic count into craft credit or sum the planes into one rubric score                                                            |
| Set prompt applicability before grading                  | Avoid inferring fixed-camera, flat-style, static-scene, interaction, occupancy, or visual-ambition requirements from implementation vocabulary | Declare one prompt profile, eligible probes, eligible craft weight, and evidence modality before inspecting competing outputs                                                                   |
| Grade runtime failures on calibrated share               | Keep each static diagnostic no broader than a locally proven defect and abstain on visibility, share, and intent ambiguity                     | Measure visible/runtime share, calibrate thresholds against a reference, and report not measurable when confidence is insufficient                                                              |
| Exercise multiple poses, time, input, and recovery paths | Diagnose statically provable setup, lifecycle, hot-loop, and resource-ownership defects                                                        | Run boot, grazing, wide, and rotated poses; idle soak; normal and rapid input; cancellation; resize; pause/resume; and privileged-API accept/reject/retry flows                                 |
| Apply hard and craft gates before scores                 | Do not claim that a clean source scan proves a rendered experience booted, completed, or achieved spatial integrity                            | Apply page/boot hard gates and the eligible experience-completeness and spatial-integrity craft gates before reporting scores                                                                   |
| Preserve every passing probe as a regression             | Keep rule tests, fuzz regressions, open-source eval evidence, pull-request parity, and the complete repository test suite green                | Re-run the full `probe.mjs` battery for each build round instead of selecting only probes related to the latest source change                                                                   |
| Use `probe.mjs` through public runtime evidence          | Do not require app-specific debug APIs or pretend lint can observe pixels, browser diagnostics, GPU counters, or temporal state                | Serve the built app and run the Playwright battery through `__THREE_DEVTOOLS__`, pixels, browser diagnostics, and synthetic input, using lite mode when its documented perturbation requires it |

| Rubric probe                              | Static coverage                                                                                                                          | Disposition                                                                                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Page errors                               | None                                                                                                                                     | Runtime-only hard gate. Source cannot establish whether a page throws over the complete exercise path.                                |

| Boot and render                           | `three-require-render-in-animation-loop`, `three-require-renderer-dom-attachment`, `three-require-renderer-size`, and R3F `Canvas` rules | Framebuffer activity and required central output remain runtime-only.                                                                 |
| Unprompted-interaction gate               | None                                                                                                                                     | Requires synthetic input before and after a documented entry flow.                                                                    |
| Privileged-input acquisition and recovery | None                                                                                                                                     | Accept, rejection, retry, and browser permission state require runtime exercise.                                                      |
| Input to response locality                | `three-valid-raycaster-range` and `r3f-valid-raycaster-range` cover invalid ray intervals only                                           | Pointer/response centroids and coordinate transforms require rendered input trials.                                                   |

| Input lifecycle                           | Controls and root cleanup rules cover owned resources, not held-state cancellation                                                       | Blur, `pointercancel`, visibility, and lock-loss behavior require runtime state observation.                                          |

Runtime share grading covers dynamic and imported scenes.            |
| Interaction jank                          | Allocation, clone, compile, readback, resize, state-update, and material-recompile loop rules catch high-confidence causes               | Long Animation Frame duration and the calibrated 200 ms threshold are runtime-only.                                                   |

## Intentionally rejected universal lint rules

- Transparency sorting, mipmap choice, z-fighting, exposure, motion continuity, containment,
  occupancy, idle churn, camera stability, and absolute performance depend on visibility, share,
  time, pixels, or prompt intent.
- Texture repetition, untextured share, spawn entropy, output color space, scene complexity, and
  fixed-camera or static-scene choices are not defects without a task-specific contract.
- Runtime and craft rows must be reported as not observed or not measurable when the required
  evidence is unavailable. Absence of a static diagnostic is never a passing craft score.
