## Why the bug exists

> Developers often reach for React Native's built-in Image because it is available by default and has a familiar API. In Expo apps that assumption misses image-specific primitives for caching, placeholders, transitions, and list performance.

## Generality check

> Expo-managed React Native apps commonly render remote images in avatars, feeds, cards, and hero sections, so the performance concern is broad. The detector keys only on the standard React Native Image import and gates to Expo-managed files, avoiding a blanket requirement for unrelated web or bare native projects.

## Validation prompt

FP-aware guidance for the [react-review agent](https://github.com/millionco/react-review):

> Confirm the file belongs to an Expo-managed React Native target, not a bare React Native package where adding Expo modules is intentionally out of scope. Typical false positives include imports used only for static helpers such as asset resolution, and tiny local bundled images where network caching or progressive loading is irrelevant. If the project already routes image rendering through a shared wrapper, check whether this import is transitional or intentionally isolated.

## Fix prompt

> Replace the React Native Image import with the Image component from expo-image in Expo-managed code. The basic source and style props usually carry over, and you can add expo-image props when helpful. Example: `import { Image } from "expo-image";` then `<Image source={{ uri }} contentFit="cover" transition={200} style={styles.avatar} />`.

## Positive fixture (SHOULD trigger)

```tsx

  return <Image source={{ uri: url }} />;
```

```tsx
import { Image } from "expo-image";

export function Avatar({ url }: { url: string }) {
```

```ts
const EMPTY_VISITORS: RuleVisitors = {};

export const preferExpoImage = defineRule<Rule>({
  id: "prefer-expo-image",
  tags: ["test-noise"],
  requires: ["react-native"],
  severity: "warn",
  recommendation:
    "Use `<Image>` from `expo-image` instead of `react-native` in Expo apps for caching, placeholders, and progressive loading",

    if (!isExpoManagedFileActive(context)) return EMPTY_VISITORS;

          if (!isNodeOfType(specifier, "ImportSpecifier")) continue;
          if (getImportedName(specifier) !== "Image") continue;
          context.report({
            node: specifier,
            message:
              "Importing Image from react-native in an Expo app — prefer expo-image for caching, placeholders, and progressive loading",
          });
        }
      },
    };
  },
});
```
